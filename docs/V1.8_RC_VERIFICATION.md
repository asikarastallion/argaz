# v1.8.0-rc.1 technical verification

Date: 2026-11-02. Baseline: v1.7.0 `12a002b`. This record distinguishes what
was observed from what remains unverified; it is not a release claim by itself.

## Environment

The local verification environment was a rootless Podman Tier 2 image on
Ubuntu 26.04. The image provides Ubuntu 24.04, ROS 2 Jazzy, Gazebo Harmonic,
pinned ArduPilot `0b38722`, and pinned SITL_Models
`25bc38ed8c6c0345840159a8cbc0b02781d52f3c`. The new
`docker/run-tier2.sh` launcher mounts the reviewed checkout read-only, with
separate writable simulation and run directories. No SO-14 source tree was
mounted, copied, or modified.

## Recovery result

No newer source was recovered. See [the recovery audit](v1.8-recovery-audit.md)
for the evidence. The model-preview UI existed in v1.7; missing preview files
were an ignored local asset set rather than a removed interface feature.

## Observed flights

| Flight | Observed state | Result |
|---|---|---|
| BiCopter Gazebo smoke, `20261102T055140Z_bicopter` | MAVLink connected and pre-arm ready; GUIDED climb reached 3.0 m; LAND descended and auto-disarmed. | **passed**: `copter_takeoff` and `copter_land` |
| Plane SITL-only, `20261102T054857Z_sitl_plane` | MAVLink connected and pre-arm ready; TAKEOFF reached 12.4 m; RTL was observed armed and flying, reaching 98.7 m. | **failed honestly**: the takeoff attitude-envelope acceptance criterion was *not judged* because only 4.5 of its required 5 seconds of ATTITUDE telemetry arrived. RTL itself passed. |

Both runs retained DataFlash, `result.json`, `evidence.json`, telemetry,
fingerprint, parameter record, plots, and a generated Markdown/JSON report.
The Plane result was not upgraded based on its ACK, altitude, or RTL state.

## Reliability checks

- Targeted launcher and preview tests: passed.
- Full launch-safety module: **55 passed** using the same read-only-source plus
  writable-work-directory mount shape as the local launcher.
- Shutdown-finalization change from PR #3: **4 passed** targeted tests. It is
  applied as commit `0f12666`; normal STOP remains non-blocking, while FastAPI
  shutdown waits for the last report writer.
- A three-run BiCopter campaign was started but did not complete: its first
  iteration remained in heartbeat waiting after a preceding manual STOP, with
  no simulator process. It must be investigated before making a repeatability
  claim. No campaign result is represented as passing.

## Release recommendation

**NO-GO for a final v1.8 release.** The recovery, local-launch and report
finalization changes are reviewable, and the BiCopter smoke test passed. The
Plane evidence failure and the incomplete repeatability campaign prevent a
reliability-release claim. Resolve and test the campaign start/cleanup path,
then repeat the three-run campaign and full Tier 1/Tier 2 checks.
