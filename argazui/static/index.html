          How to Use
          
      
    
          

    
          
      
            
        
          1. Pick a model. Choose one from the COPTER / PLANE / VTOL columns.
            The right-hand panel shows a preview and how it will be launched.
            2. 
        
          2. ▶ START. Gazebo, SITL and MAVProxy come up. The commands are typed
            into the SIMULATION terminal verbatim, so you can see exactly what ran.
            3. 
        
          3. Wait for READY. ARM is rejected until the
            READY chip in the top bar turns green. This is
            normal — the autopilot needs to settle its sensors and set a home
            position (usually 10–35 s).
            4. 
        
          4. Fly. The Quick Commands change with the vehicle class. Every result
            is written to the terminal; if a command is rejected, the autopilot's own
            reason is shown.
            5. 
        
          5. Run a mission script (optional). Python files in scripts/
            are listed here and run in the COMMAND tab.
            6. 
        
          6. ■ STOP. Gazebo, SITL, MAVProxy and RViz are shut down cleanly.
            7. 
        
          7. Read the run. The session is archived under
            runs/<UTC-time>_<model>/ and appears in
            FLIGHT RUNS: the console log, the MAVLink events, every
            parameter, the autopilot's dataflash log, and a report built from
            it (mode timeline, altitude and attitude plots, vibration, EKF).
            8. 
      
          

      
          The terminal tabs
          
      
          
        
          SIMULATION
            Gazebo / SITL / MAVProxy run here. For models launched with
                sim_vehicle.py, MAVProxy is interactive — you can type
                status, wp list or
                motortest 1 1 1005 2 straight into it.
          
        
          COMMAND / SCRIPT
            A plain bash shell. Mission scripts run here, and you can type any
                shell command.
          
        
          FLEET LAUNCH
            A read-only transcript of the exact command line each fleet
                vehicle was started with, including its instance number, its
                sysid and its home. Not a shell — it is the record of what ran.
          
      
          
      
          Why not one terminal per vehicle? A fleet of four would
        mean four consoles nobody watches. There are three, whatever the fleet
        size: the transcript above, one attach console for the vehicle
        you are focused on, and the free shell.
          


      
          FLEET — flying more than one vehicle
          
      
          The FLEET tab at the top of the page is a second, separate
        path. Everything above still works exactly as it did; a fleet does not
        change how a single vehicle flies.
          
      
            
        
          1. Pick a fleet. Fleets are declared in files, not in the
            interface: argazui/config/fleets/<name>.toml.
            That file is copied into the run directory, so running the same
            file twice is what makes two runs comparable.
            2. 
        
          2. Check the badge. A fleet that does not validate cannot be
            started, and the badge says why — a duplicate sysid, a model
            tier 2 has not passed, two vehicles spawning too close together.
            Nothing is launched to find this out. The same check runs from the
            command line: argazui fleet validate <name>.
            3. 
        
          3. ▶ START FLEET. Vehicles come up one stage at a time, and
            each stage has to pass before the next begins. A stage that times
            out fails the run rather than hoping.
            4. 
        
          4. Choose a target. All or Selected, with the
            tick boxes on the cards. The command buttons show how many vehicles
            they will reach before you press them — ARM → 2
            means two, and ARM → none is disabled.
            5. 
        
          5. Read the ACK matrix, not the fact that a command was sent.
            See below.
            6. 
        
          6. ■ STOP FLEET. Vehicles first, then the physics server, then
            the port leases, then a sweep for anything left running.
            7. 
      
          

      
          An ACK is not a result
          
      
          An autopilot can accept a command and then not do it. This was
        measured on this project: ArduPlane accepted a mode change and was back
        in the previous mode 140 ms later, with no rejection and no message.
        So every vehicle gets one of five answers:
          
      
          
        
          ACCEPTEDacknowledged, and the state still held
            afterwards
          
        
          REVERTEDacknowledged, and the vehicle did not
            stay in that state. Shown in its own colour — this is not a
            success
          
        
          DENIEDrefused, with the autopilot's own wording
          
        
          TIMEOUTno acknowledgement arrived in time
          
        
          NO_LINKthere was no link to acknowledge it
          
      
          
      
          The outcome words are deliberately left in English: they
        are exactly what fleet.json, timeline.jsonl
        and fleet_report.md record, so a row on screen can be
        matched to the file it came from.
          

      
          NOT MEASURED is not a pass
          
      
          The separation and real-time-factor panels sometimes say
        NOT MEASURED with a reason instead of showing a number. That is
        a result, not a fault:
          
      
            
        
          • A fleet without Gazebo has no physics server, so there is no
            real-time factor to report — and its vehicles do not share a clock,
            so a distance computed between two of them would not be a distance.
            Both panels say so.
            • 
        
          • With Gazebo, separation comes from the world state itself — one
            message carrying every model's position at one instant — rather
            than from each vehicle's own idea of where it is.
            • 
      
          
      
          A blank, a zero or a grey dash would all read as "fine".
        The panel says what was not measured and why, in the same words the
        run's report uses.
          
      
          MAVLink ports
          
      
          
        
          14550ArgazUI — quick command buttons and the status chips
          
        
          14551Your mission scripts. Two listeners cannot share one UDP
            port, which is why they are split — use 14551 in your scripts.
          
        
          14552Live plot. ArgazUI sends telemetry here while a
            vehicle runs; point PlotJuggler at it (Streaming → UDP Server)
            to watch the flight as a graph. Address 127.0.0.1, Port
            14552, Message Protocol JSON. Put only the bare
            host in Address: a host:port string there makes
            PlotJuggler show "Couldn't bind to IPv4 UDP server" even though
            it is receiving fine — and pressing OK on that dialog is what stops
            the stream. See the LIVE PLOT line under Quick Commands.
          
      
          

      
          Common situations
          
      
          
        
          ARM rejected
            Almost always the vehicle is not ready yet. Wait for READY to turn
                green and try again. The reason appears in the terminal (e.g.
                Arm: AHRS: waiting for home).
          
        
          AUTO does nothing
            Without a loaded mission the autopilot will not stay in AUTO and falls
                back to RTL. That is not a bug.
          
        
          RViz does not open
            RViz and the ROS 2/DDS bridge exist only for Iris. Other models do not
                have that stack; the panel states "RViz/DDS: no".
          
        
          Buttons are dimmed
            They activate when a vehicle is running and MAVLink is connected.
          
      
          

      
          For more detail (adding models, buttons and scripts,
        troubleshooting) see argazui/USAGE.md in the project folder.
          
    
          

    
          
      
            
        
          1. Model seç. Soldaki COPTER / PLANE / VTOL sütunlarından birini işaretle.
            Sağdaki panelde aracın önizlemesi ve nasıl başlatılacağı görünür.
            2. 
        
          2. ▶ BAŞLAT. Gazebo, SITL ve MAVProxy açılır. Komutlar SİMÜLASYON
            terminaline aynen yazılır — ne çalıştırıldığını görebilirsin.
            3. 
        
          3. HAZIR göstergesini bekle. Üst çubuktaki
            HAZIR yeşile dönmeden ARM reddedilir.
            Bu normaldir: otopilotun sensörleri oturması ve ev konumunu belirlemesi
            gerekir (genelde 10–35 sn).
            4. 
        
          4. Uçur. Hızlı Komutlar bölümündeki butonlar aracın sınıfına göre
            değişir. Her komutun sonucu terminale yazılır; reddedilirse otopilotun
            gerekçesi de görünür.
            5. 
        
          5. Görev scripti çalıştır (isteğe bağlı). scripts/
            klasöründeki Python dosyaları listelenir, KOMUT sekmesinde çalışırlar.
            6. 
        
          6. ■ DURDUR. Gazebo, SITL, MAVProxy ve RViz temizce kapatılır.
            7. 
        
          7. Koşuyu oku. Oturum
            runs/<UTC-zaman>_<model>/ altına arşivlenir ve
            UÇUŞ KOŞULARI panelinde görünür: konsol kaydı, MAVLink
            olayları, tüm parametreler, otopilotun dataflash logu ve ondan
            üretilen rapor (mod zaman çizelgesi, irtifa ve tutum grafikleri,
            titreşim, EKF).
            8. 
      
          

      
          Terminal sekmeleri
          
      
          
        
          SİMÜLASYON
            Gazebo / SITL / MAVProxy burada çalışır. sim_vehicle.py ile
                açılan modellerde MAVProxy etkileşimlidir — buraya status,
                wp list, motortest 1 1 1005 2 gibi komutları
                elle yazabilirsin.
          
        
          KOMUT / SCRIPT
            Boş bir bash kabuğu. Görev scriptleri burada çalışır; istediğin kabuk
                komutunu da yazabilirsin.
          
        
          FİLO BAŞLATMA
            Filodaki her aracın hangi komut satırıyla başlatıldığının birebir
                kaydı — instance numarası, sysid'i ve home'u dahil. Kabuk değildir;
                ne çalıştığının kaydıdır.
          
      
          
      
          Neden araç başına bir terminal yok? Dört araçlık bir filo,
        kimsenin bakmadığı dört konsol demek olurdu. Filo kaç araçlı olursa olsun
        üç tane var: yukarıdaki kayıt, odaklandığın araç için tek bir
        konsola bağlan, ve serbest kabuk.
          


      
          FİLO — birden fazla araç uçurmak
          
      
          Sayfanın üstündeki FİLO sekmesi ikinci ve ayrı bir yoldur.
        Yukarıdaki her şey aynen çalışmaya devam eder; filo, tek aracın nasıl
        uçtuğunu değiştirmez.
          
      
            
        
          1. Filo seç. Filolar arayüzde değil, dosyada tanımlanır:
            argazui/config/fleets/<ad>.toml. Bu dosya koşu
            dizinine kopyalanır; aynı dosyayı iki kez çalıştırmak, iki koşuyu
            karşılaştırılabilir yapan şeydir.
            2. 
        
          2. Rozete bak. Doğrulamayı geçmeyen filo başlatılamaz ve rozet
            nedenini söyler — tekrarlanan sysid, tier 2'yi geçmemiş bir
            model, birbirine fazla yakın iki spawn noktası. Bunu öğrenmek için
            hiçbir şey başlatılmaz. Aynı kontrol komut satırından da çalışır:
            argazui fleet validate <ad>.
            3. 
        
          3. ▶ FİLOYU BAŞLAT. Araçlar aşama aşama açılır; her aşamanın
            kapısı geçilmeden sonraki başlamaz. Zaman aşımına uğrayan bir aşama,
            "herhalde olmuştur" demek yerine koşuyu başarısız sayar.
            4. 
        
          4. Hedef seç. Tümü ya da Seçili — kartlardaki
            kutucuklarla. Komut butonları, basmadan önce kaç araca
            gideceğini yazar: ARM → 2 iki araç demektir,
            ARM → yok ise buton kapalıdır.
            5. 
        
          5. ACK matrisini oku; komutun gönderilmiş olmasını değil.
            Aşağıya bakın.
            6. 
        
          6. ■ FİLOYU DURDUR. Önce araçlar, sonra fizik sunucusu, sonra
            port kiraları, en son da geride kalan bir şey var mı diye tarama.
            7. 
      
          

      
          ACK bir sonuç değildir
          
      
          Bir otopilot komutu kabul edip yapmayabilir. Bu, bu projede ölçüldü:
        ArduPlane bir mod değişimini kabul etti ve 140 ms sonra eski moduna
        dönmüştü — ne bir ret, ne bir mesaj. Bu yüzden her araç beş cevaptan
        birini alır:
          
      
          
        
          ACCEPTEDkabul edildi ve durum sonrasında da korundu
          
        
          REVERTEDkabul edildi ama araç o durumda kalmadı.
            Kendi rengiyle gösterilir — bu bir başarı değildir
          
        
          DENIEDreddedildi; otopilotun kendi ifadesiyle
          
        
          TIMEOUTzamanında hiçbir onay gelmedi
          
        
          NO_LINKonaylayacak bir bağlantı yoktu
          
      
          
      
          Sonuç sözcükleri bilerek İngilizce bırakıldı:
        fleet.json, timeline.jsonl ve
        fleet_report.md tam olarak bunları kaydeder, böylece
        ekrandaki satır geldiği dosyayla eşleştirilebilir.
          

      
          ÖLÇÜLMEDİ, "sorun yok" demek değildir
          
      
          Ayrışma ve gerçek zaman çarpanı panelleri bazen sayı yerine gerekçesiyle
        birlikte ÖLÇÜLMEDİ yazar. Bu bir arıza değil, bir sonuçtur:
          
      
            
        
          • Gazebo'suz bir filoda fizik sunucusu yoktur, dolayısıyla
            raporlanacak bir gerçek zaman çarpanı da yoktur — ve araçlar ortak
            bir saat paylaşmadığı için ikisi arasında hesaplanan bir mesafe,
            mesafe olmaz. İki panel de bunu söyler.
            • 
        
          • Gazebo varken ayrışma, her aracın kendi konum tahmininden değil,
            dünyanın durumundan okunur: tek bir mesajın tek bir anda taşıdığı
            tüm model konumlarından.
            • 
      
          
      
          Boş bırakmak, sıfır yazmak ya da gri bir tire koymak —
        üçü de "sorun yok" diye okunurdu. Panel, neyin ölçülmediğini ve nedenini,
        koşunun raporundaki ifadelerle söyler.
          
      
          MAVLink portları
          
      
          
        
          14550ArgazUI — hızlı komut butonları ve üstteki göstergeler
          
        
          14551Senin görev scriptlerin. Aynı porta iki dinleyici
            bağlanamadığı için ayrıldılar; scriptlerinde 14551 kullan.
          
        
          14552Canlı grafik. Araç çalışırken ArgazUI telemetriyi buraya
            gönderir; PlotJuggler'ı bu porta yönlendirirsen
            (Streaming → UDP Server) uçuşu anlık grafik olarak izlersin.
            Address 127.0.0.1, Port 14552, Message
            Protocol JSON. Address kutusuna yalnızca host yaz:
            oraya host:port yazarsan PlotJuggler veriyi sorunsuz
            aldığı halde "Couldn't bind to IPv4 UDP server" uyarısı verir
            — ve akışı durduran şey o pencerede OK'a basmaktır. Hızlı
            Komutlar'ın altındaki CANLI GRAFİK satırına bak.
          
      
          

      
          Sık karşılaşılanlar
          
      
          
        
          ARM reddedildi
            Neredeyse her zaman araç henüz hazır değildir. HAZIR yeşile
                dönünce tekrar dene. Gerekçe terminalde yazar (ör.
                Arm: AHRS: waiting for home).
          
        
          AUTO çalışmıyor
            Yüklü bir görev (waypoint) yoksa otopilot AUTO'da kalmaz, RTL'e düşer.
                Bu bir hata değildir.
          
        
          RViz açılmıyor
            RViz ve ROS2/DDS köprüsü yalnızca Iris'te vardır. Diğer modellerde bu
                altyapı yoktur; panel bunu "RViz/DDS: yok" diye belirtir.
          
        
          Butonlar soluk
            Bir araç çalışıyor ve MAVLink bağlıyken aktifleşirler.

        retyping the same commands for every attempt.
