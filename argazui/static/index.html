          Engineering documentation

          How to Use

          1. Pick a model. Choose one from the COPTER / PLANE / VTOL columns. The right-hand panel shows a preview and how it will be launched.
          2. ▶ START. Gazebo, SITL and MAVProxy come up. The commands are typed into the SIMULATION terminal verbatim, so you can see exactly what ran.
          3. Wait for READY. ARM is rejected until the READY chip in the top bar turns green. This is normal — the autopilot needs to settle its sensors and set a home position (usually 10–35 s).
          4. Fly. The Quick Commands change with the vehicle class. Every result is written to the terminal; if a command is rejected, the autopilot's own reason is shown.
          5. Run a mission script (optional). Python files in scripts/ are listed here and run in the COMMAND tab.
          6. ■ STOP. Gazebo, SITL, MAVProxy and RViz are shut down cleanly.
          7. Read the run. The session is archived under runs/<UTC-time>_<model>/ and appears in FLIGHT RUNS: the console log, the MAVLink events, every parameter, the autopilot's dataflash log, and a report built from it (mode timeline, altitude and attitude plots, vibration, EKF).

          The two terminal tabs

          SIMULATION Gazebo / SITL / MAVProxy run here. For models launched with sim_vehicle.py, MAVProxy is interactive — you can type status, wp list or motortest 1 1 1005 2 straight into it.
          COMMAND / SCRIPT A plain bash shell. Mission scripts run here, and you can type any shell command.

          Why two terminals? The simulation occupies the shell's foreground — that is required for MAVProxy to keep reading the keyboard — so running a script needs a second shell.

          MAVLink ports

          14550ArgazUI — quick command buttons and the status chips
          14551Your mission scripts. Two listeners cannot share one UDP port, which is why they are split — use 14551 in your scripts.
          14552Live plot. ArgazUI sends telemetry here while a vehicle runs; point PlotJuggler at it (Streaming → UDP Server) to watch the flight as a graph. Address 127.0.0.1, Port 14552, Message Protocol JSON. Put only the bare host in Address: a host:port string there makes PlotJuggler show "Couldn't bind to IPv4 UDP server" even though it is receiving fine — and pressing OK on that dialog is what stops the stream. See the LIVE PLOT line under Quick Commands.

          Common situations

          ARM rejected Almost always the vehicle is not ready yet. Wait for READY to turn green and try again. The reason appears in the terminal (e.g. Arm: AHRS: waiting for home).
          AUTO does nothing Without a loaded mission the autopilot will not stay in AUTO and falls back to RTL. That is not a bug.
          RViz does not open RViz and the ROS 2/DDS bridge exist only for Iris. Other models do not have that stack; the panel states "RViz/DDS: no".
          Buttons are dimmed They activate when a vehicle is running and MAVLink is connected.

          For more detail (adding models, buttons and scripts, troubleshooting) see argazui/USAGE.md in the project folder.

          Terminalin iki sekmesi

          SİMÜLASYON Gazebo / SITL / MAVProxy burada çalışır. sim_vehicle.py ile açılan modellerde MAVProxy etkileşimlidir — buraya status, wp list, motortest 1 1 1005 2 gibi komutları elle yazabilirsin.

          Sık karşılaşılanlar

          ARM reddedildi Neredeyse her zaman araç henüz hazır değildir. HAZIR yeşile dönünce tekrar dene. Gerekçe terminalde yazar (ör. Arm: AHRS: waiting for home).
          AUTO çalışmıyor Yüklü bir görev (waypoint) yoksa otopilot AUTO'da kalmaz, RTL'e düşer. Bu bir hata değildir.
          RViz açılmıyor RViz ve ROS2/DDS köprüsü yalnızca Iris'te vardır. Diğer modellerde bu altyapı yoktur; panel bunu "RViz/DDS: yok" diye belirtir.
          Butonlar soluk Bir araç çalışıyor ve MAVLink bağlıyken aktifleşirler.
